# Changelog

Schema and data changes to the harmonized datasets, newest last. The schema version lives in
[`scripts/schema.py`](../scripts/schema.py) (`SCHEMA_VERSION`, `VOTE_COUNTING_SCHEMA_VERSION`);
column-level documentation is in [`data-dictionary.md`](data-dictionary.md). (Before 2026-10-26
this log was §9 of the data dictionary.)

- **2026-05-23** — Schema 1.0.0 released alongside the new pipeline. Initial dictionary published.
- **2026-05** — Added `discover.py` (BoCo + SOS upstream scraping), pytest suite under `tests/`, CI workflow at `.github/workflows/tests.yml`, plus 2025 Boulder coordinated + 2024 SOS general entries. `infer_contest_type` now handles `pd.NA` inputs.
- **2026-05** — Schema bumped to **1.1.0**. Per-row CSVs now hold a slim 15-column view; the 5 provenance columns (`source_file`, `source_url`, `retrieved_at`, `extraction_quality`, `extraction_notes`) moved to `data/processed/statements-of-votes/provenance.csv`. Combined-CSV size dropped from 152 MB to 49 MB; per-year files shrank by ~60%.
- **2026-10** — Added the election-night incremental results dataset (data dictionary §8, vote-counting schema 1.0.0), OCR'd from results-site screenshots via Datalab. Boulder SoV raw files moved to `data/original/boulder-county/statement-of-votes/`; paths now resolve through `config.original_path()`.
- **2026-10** — Boulder tidy parser keeps `Property Owner` pseudo-precinct rows (2023, 2025) instead of rejecting them (data dictionary §4.3a).
- **2026-10** — Accuracy fixes (data changes; schema unchanged):
  - SOS 2012-2020: every judge's retention votes kept, one contest per judge (`Court of Appeals - {judge}`); no more 0-vote `Yes`/`No` rows on candidate contests or 0-vote judge "candidate" rows (data dictionary §4.5). Boulder retention votes per year now equal the raw file's (e.g. 2016: 400,831 → 1,701,522).
  - Boulder 2008/2010 panel files re-parsed with positional alignment; 2008 grows from 2,528 to 27,934 rows and every candidate reconciles to the file's `Totals` row (data dictionary §4.2). 2011/2012 gain their `Landowner` rows.
  - PDF years: candidate headers read per page; no duplicate keys; every candidate reconciles to the PDF's printed totals (data dictionary §4.4).
  - `For/Against the Measure`, `FOR THE ISSUE`, `FOR`/`AGAINST` → `Yes`/`No` (contest type `measure`); county/district court judges typed `retention`, TABOR revenue-retention questions typed `measure`.
  - Party codes unified across sources (`UNI`/`Unity Party of Colorado` → `UTY`, `LIB` → `LBR`, `UNA` → `UAF`, `APV` → `AVP`, full names → codes; see `data/lookups/party-codes.json`).
  - `provenance.csv` has a row for every source file, including the PDF years and the turnout-only 2024 SOS file; `reconcile.py` adds a contest × candidate check.
- **2026-10** — Pipeline and provenance: filtered runs no longer overwrite the whole-dataset outputs (combined CSV, provenance, rejects, audit summary, reconciliation, election-night CSVs); `fetch` records and keeps files already on disk and verifies hashes (`--verify`); the Datasette database is built from the committed per-year CSVs, so it now has all 22 years (2005/2007/2009 were missing); the annual refresh targets the previous year. Election-night: the duplicate 2023 RCV final report rows are dropped (one row per candidate and round per report time), and the Round-N semantics are documented (data dictionary §3).
- **2026-10** — Schema **1.2.0**: new `is_pseudo_precinct` boolean (appended after `ballots_cast`; CSVs are now 16 columns), and composite precinct IDs use one `", "` separator (data dictionary §4.3). Glossary (data dictionary §0); precinct-ID widths by year (data dictionary §2.1); every pseudo-precinct variant listed (data dictionary §4.3a); counts in §5 generated by `scripts/doc_stats.py`.
- **2026-10** — Conventions aligned with BoulderPublicData/Cast-Vote-Records (#34): one election key, lowercase `{year}-{type}` with `type` ∈ {`general`, `primary`, `coordinated`} (`scripts.sources.election_key`). The election-night Datalab cache folders are renamed `datalab/2016G/` → `datalab/2016-general/` and `vote_counting --election` takes the key (`--election 2016-general`; the old `2016G` still parses). The raw folders under `data/original/boulder-county/vote-counting/` keep their published names, so `source_file` paths are unchanged. The changelog moved here from the data dictionary; a shared glossary is at [`glossary.md`](glossary.md); CI tests the Python floor (3.11) and the latest supported (3.13).
- **2026-11** — Recounts, the full 2024 SoV, one correction and one title (#42–#46); schema unchanged:
  - **Recount / amended SoVs are merged by contest** (`scripts/overlay.py`, `Source.supplements`; data dictionary §4.7). 2023: the committed workbook is the November original (its registry URL said "Recount"); the December recount is added as `2023-coordinated-sov-recount.xlsx` and replaces City of Boulder Council Candidates (113,379 → 113,374 votes). 2024: the full Statement of Votes (`2024-general-sov.xlsx`, 18,438 rows, 65 contests) replaces the 66-row amended file as the source, and the amended file (renamed `2024-general-sov-amended.xlsx`, bytes unchanged) replaces its 2 contests: 6,649,407 votes, against 27,884 before.
  - **Adjudicated SoV corrections** (`scripts/corrections/statements-of-votes.csv`, data dictionary §4.8). 2023 Louisville City Council Ward 2: the duplicated unit `2181207202, 2181207500` is dropped, giving Fahey 1,419 and Colbert 1,207 (were 1,602 / 1,441), as in the county's Summary of Votes and final election-night update. `reconcile` reports the two keys as `corrected`.
  - **2011 panel title:** Mountains Forest Improvement District Question 5C was titled `161` (its title starts with "Boulder County", which was skipped as the page banner); it is now `Boulder County Mountains Forest Improvement District Question 5C:`. No other 2008–2012 title changes.
  - **Election types:** `presidential_primary` (key `{year}-presidential-primary`, county prefix `2024PP`) joins the shared vocabulary with Cast-Vote-Records; no data ingested. Discovery classifies presidential-primary files and attaches recount / amended files to the full SoV as supplements instead of preferring them.
  - Data dictionary §8: a note that 2016 `total_ballots_counted` exceeds the county's election-day ballot returns (+1.68%), unlike 2017–2025 (#45).
